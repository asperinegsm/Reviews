# Mini-PRD: Review-платформа для СНГ (MVP)

## 1) Цель продукта
Сделать SaaS-платформу для малого бизнеса и сетей в СНГ, которая помогает:
- собирать больше отзывов,
- повышать средний рейтинг,
- быстро отвечать на отзывы,
- отслеживать метрики по филиалам и каналам.

## 2) Целевая аудитория
- Малый бизнес: медицина, автосервисы, салоны красоты, аптеки и др.
- Сетевые компании с несколькими филиалами.

## 3) Каналы и платформы (приоритет)
### Обязательные каналы
1. Telegram
2. SMS

### Следующие каналы
1. MAX
2. Viber

### Площадки отзывов
1. Google
2. 2GIS
3. Яндекс
4. Локальные каталоги по странам СНГ

## 4) MVP-функционал
1. **Личный кабинет** с ролями (владелец, менеджер, оператор).
2. **Филиалы/локации**: создание, редактирование, статистика по точкам.
3. **Запросы на отзыв**: отправка через Telegram/SMS после услуги.
4. **Review-link + QR**: персональная ссылка для каждого филиала.
5. **Маршрутизация обратной связи**:
   - 4–5 звезд → внешние площадки,
   - 1–3 звезды → внутренний фидбек.
6. **Лента отзывов**: фильтры, статусы, карточка отзыва.
7. **Ответы на отзывы**: шаблоны + AI-черновик ответа (RU-first).
8. **Виджеты для сайта**: сетка/карусель.
9. **Дашборд**: рейтинг, динамика, конверсия по воронке.

## 5) Нефункциональные требования
- Локализация интерфейса: RU по умолчанию, затем мультиязычность.
- Надежность: логирование, алерты, мониторинг.
- Безопасность: RBAC, аудит-лог, хранение персональных данных по правилам региона.
- Масштабируемость: поддержка мультифилиальных клиентов.

## 6) Предложение по стеку
- **Frontend**: Next.js (React + TypeScript).
- **Backend API**: Go (Gin/Fiber).
- **Интеграции и AI-пайплайн**: Python (FastAPI + worker).
- **DB**: PostgreSQL.
- **Queue/Cache**: Redis.
- **Инфраструктура**: Docker Compose (MVP), затем Kubernetes при росте.

> Упрощенный вариант для первого релиза: все backend-сервисы на Python (FastAPI), затем вынос нагруженных частей в Go.

## 7) Экранная модель MVP
1. Главная (dashboard)
2. Отзывы
3. Запросы (создать/история)
4. Шаблоны
5. Виджеты
6. Профиль компании
7. Настройки интеграций
8. Команда и роли

## 8) События аналитики (минимум)
- request_sent
- request_delivered
- request_opened
- link_clicked
- review_left
- feedback_internal
- review_answered

## 9) План запуска (8 недель)
- **Недели 1–2**: дизайн прототипа, auth, компании/филиалы.
- **Недели 3–4**: Telegram/SMS отправка, review-link, лента отзывов.
- **Недели 5–6**: интеграции площадок, ответы и AI-черновики.
- **Недели 7–8**: виджеты, стабилизация, пилот с 2–3 клиентами.

# Как новичку приступить к разработке (пошагово)

## Шаг 1. Установить базовые инструменты
- Git
- Docker + Docker Compose
- VS Code
- Node.js LTS
- Python 3.11+
- Go 1.22+

## Шаг 2. Создать структуру проекта
Рекомендуемая структура:

```
reviews/
  apps/
    web/            # Next.js
    api-go/         # Go API
    api-python/     # Python integrations/AI
  packages/
    ui/
    config/
  infra/
    docker/
  docs/
```

## Шаг 3. Начать с одного вертикального сценария
Сделать флоу целиком:
1) создать филиал,
2) отправить запрос,
3) получить ответ,
4) записать в БД,
5) показать в дашборде.

Так проще учиться: одна законченная “цепочка” вместо распыления на 20 функций.

## Шаг 4. Минимальный бэклог новичка (первые 10 задач)
1. Авторизация (email + пароль)
2. CRUD компаний
3. CRUD филиалов
4. Создание review-link
5. Генерация QR
6. Отправка в Telegram
7. Отправка SMS
8. Сохранение входящих отзывов
9. Список отзывов с фильтрами
10. Базовый dashboard

## Шаг 5. Как использовать Codex эффективно
1. Дай задачу с контекстом: “Вот файл, вот цель, вот ограничение”.
2. Проси маленькими шагами: по 1–2 функции за запрос.
3. После каждого шага запускай тесты/линтер.
4. Проси объяснение изменений “для новичка”.
5. Фиксируй правила в `docs/` (архитектура, naming, workflow).

## Шаг 6. Режим разработки на каждый день
- 60–90 минут на одну конкретную задачу.
- Коммит после каждой рабочей подзадачи.
- В конце дня: “что сделано / что сломалось / что дальше”.

## Шаг 7. Что НЕ делать в начале
- Не пытаться сразу делать идеальную архитектуру.
- Не подключать все каналы одновременно.
- Не запускать платную рекламу до пилота и первых метрик retention.

## Шаг 8. Критерии готовности MVP
- 3 пилотных клиента ведут работу в кабинете 2+ недели.
- Есть стабильная отправка через Telegram/SMS.
- Есть рост числа отзывов по сравнению с “до внедрения”.
- Есть базовые отчеты по филиалам.
