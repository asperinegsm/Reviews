# Phase 1 (Core MVP): что делаем в первую очередь


## 0) Обновленный приоритет (важно)
По решению команды, первый фокус — **сайт и удобный дизайн**, затем интеграции.

Порядок работ:
1. UX/UI и frontend-флоу.
2. Подключение backend core.
3. Интеграции (Telegram, скраперы, AI-ответы).

Подробный roadmap: `docs/SITE_FIRST_ROADMAP_RU.md`.

---

Этот документ фиксирует **минимальный обязательный функционал**, с которого начинаем.
Главная идея: сначала запустить рабочее ядро, потом поэтапно расширять.

## 1) Функция №1: Перехват негатива (Review Funnel + QR)

### 1.1 Конструктор review-страницы
Система должна позволять создавать несколько review-страниц (по компаниям/филиалам/акциям):
- Название страницы (внутреннее).
- Публичный URL.
- Генерация QR-кода.
- Лого/название компании.
- Настраиваемый приветственный текст.
- Порог позитива (ползунок): например, `>= 4` звезд считается позитивом.
- Выбор внешних площадок для публикации позитива (Google, Яндекс, 2GIS).
- Настройка списка локаций (если у компании несколько точек).

### 1.2 Сценарий клиента после перехода по ссылке/QR
1. Клиент видит брендированную страницу и ставит оценку (звезды).
2. Если оценка попадает в позитивный диапазон:
   - показываем сообщение благодарности,
   - показываем кнопки площадок (Google / Яндекс / 2GIS — что включено в настройках),
   - при клике отправляем пользователя на выбранную площадку оставить отзыв.
3. Если оценка попадает в негативный диапазон:
   - показываем форму обратной связи,
   - поля: описание проблемы + телефон,
   - после отправки заявка уходит владельцу бизнеса в Telegram.
4. Если включены локации:
   - после выбора звезд клиент выбирает локацию, где обслуживался,
   - далее идет позитивный/негативный сценарий.

### 1.3 Счетчики и аналитика по ссылке
По каждой review-странице нужно хранить:
- Кол-во переходов по ссылке/QR.
- Кол-во выставленных оценок.
- Кол-во позитивных оценок.
- Кол-во негативных оценок.
- Кол-во кликов на внешние площадки.
- Кол-во случаев: звезду поставили, но на площадку не перешли.
- Разрез по локациям.

## 2) Функция №2: Мониторинг отзывов + полуавтоответ

### 2.1 Мониторинг (через скрапинг-ботов)
Для подключенных площадок (Google/Яндекс/2GIS):
- Боты периодически проверяют страницу компании.
- Если найден новый отзыв:
  - копируем данные отзыва в систему,
  - сохраняем в БД,
  - отправляем уведомление пользователю (в интерфейсе + Telegram).
- Если новых отзывов нет — ничего не делаем.

### 2.2 Страница "Отзывы"
Нужен единый список отзывов со статусами:
- Новый / Отвечен / В работе.
- Фильтры: площадка, филиал, статус, дата.

Под каждым неотвеченным отзывом:
- кнопка **"Написать ответ"**,
- кнопка **"Сгенерировать ответ"**.

### 2.3 Генерация ответа (AI-ассистент)
Логика:
1. Пользователь может написать свой черновик.
2. Нажимает "Сгенерировать ответ".
3. Система генерирует итоговый текст с учетом:
   - черновика пользователя,
   - настроек стиля,
   - длины/объема ответа,
   - системного промпта компании.

### 2.4 Публикация ответа (MVP-режим)
После нажатия **"Готово"**:
- текст копируется в буфер обмена пользователя,
- система открывает страницу ответа на площадке,
- пользователю остается вставить текст и отправить.

> Важно: на первом этапе не делаем автопубликацию от имени пользователя, только copy-to-clipboard + redirect.

## 3) Что НЕ делаем на первом этапе
- Полный CRM-модуль.
- Сложная биллинг-система.
- Полноценная автопубликация ответов через API всех площадок.
- Сложная BI-аналитика и прогнозы.
- MAX/Viber (добавляем после стабильного релиза Telegram + базового мониторинга).

## 5) Очередность реализации (практично)

### Итерация A (1–2 недели)
- Конструктор review-страницы.
- Публичная страница со звездами.
- Позитив/негатив ветвление.
- Отправка негатива в Telegram.
- Базовые счетчики.

### Итерация B (1–2 недели)
- Множественные локации в сценарии.
- Несколько ссылок/QR на аккаунт.
- Улучшение аналитики (конверсии по шагам).

### Итерация C (2 недели)
- Мониторинг отзывов скрапинг-ботами.
- Единая страница отзывов.
- Уведомления о новых отзывах.

### Итерация D (1–2 недели)
- AI-генерация ответов + настройки промптов.
- Copy-to-clipboard + переход на страницу ответа.

## 6) Техническая рекомендация для старта (новичку)
Чтобы не перегружаться архитектурой:
- 1 backend (Python/FastAPI),
- 1 frontend (Next.js),
- PostgreSQL,
- Redis (очереди/кэш),
- Celery/RQ для задач мониторинга,
- Telegram Bot API для оповещений.

После стабилизации можно выносить высоконагруженные части в Go.
