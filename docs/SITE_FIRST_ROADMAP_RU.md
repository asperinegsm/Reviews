# Site-first roadmap: сначала сайт и дизайн, потом интеграции

Этот план фиксирует новый приоритет:
1) сначала делаем удобный сайт/кабинет и UX,
2) затем подключаем интеграции и автоматизации.

---

## 1) Что делаем в первую очередь (Design-first)

### Этап A — UX/UI каркас (1–2 недели)
- Информационная архитектура: меню, разделы, пути пользователя.
- Дизайн-система: цвета, типографика, отступы, состояния кнопок/форм.
- Адаптивные макеты: desktop + tablet + mobile.
- Прототипы ключевых экранов:
  - Landing
  - Dashboard
  - Конструктор review-страницы
  - Публичная страница оценки (звезды)
  - Лента отзывов

### Этап B — Frontend без интеграций (2–3 недели)
- Реализовать интерфейс в Next.js с мок-данными.
- Реализовать полный пользовательский флоу:
  - создание review-страницы,
  - генерация ссылки/QR (UI + заглушка backend),
  - выбор звезд,
  - позитивная/негативная ветка,
  - страницы благодарности/обратной связи,
  - страница отзывов и модалка генерации ответа.
- Подготовить локализацию RU как базовую.

### Этап C — Backend core (1–2 недели)
- Подключить БД и API к уже готовому UI.
- Сохранение страниц, рейтингов, негативных форм и событий аналитики.
- Базовая авторизация и роли.

### Этап D — Интеграции (после готового UX)
- Telegram-уведомления по негативу.
- Мониторинг отзывов на площадках (скраперы).
- AI-генерация ответов.
- Ссылки на Google/Яндекс/2GIS.

---

## 2) Критерии готовности сайта до интеграций
Считаем “дизайн и интерфейс готовы”, если:
- Пользователь может пройти основной путь от входа до сценария оценки без багов UI.
- Есть единый стиль и предсказуемые компоненты.
- Время загрузки ключевых экранов в норме.
- Мобильная версия не ломается на основных разрешениях.
- Понятные тексты/CTA на русском языке.

---

## 3) Минимальный стек для design-first старта
- Next.js + TypeScript
- Tailwind CSS (или shadcn/ui)
- Storybook (по желанию, для компонентов)
- Mock Service Worker / JSON mocks

Интеграции/API включаем после стабилизации интерфейсов.

---

## 4) Что это дает
- Быстрый визуальный результат и понятная демо-версия.
- Проще собирать обратную связь от клиентов до сложной backend-части.
- Меньше переделок API, потому что UX-флоу уже проверены.
